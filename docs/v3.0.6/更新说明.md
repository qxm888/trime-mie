# V3.0.6 开机初始化修复

正式版本 V3.0.6 / 20261204，正式包 trime-mie-v3.0.6.apk。

## 本轮定位

用户报告关机开机后，首次解锁前或刚解锁时退出。提供的V3.0.5日志没有那次异常堆栈；通过手机正式应用自身的退出记录，可确认2026-10-30 08:00:18状态10的异常处理退出，以及08:00:24状态0的解锁切换退出。原有自定义异常处理未同步保存堆栈，后续普通日志无法还原该次异常。

检查代码发现两条明确的启动隐患：一是多个模块把设备保护上下文换回applicationContext，可能在首次解锁前访问仍锁定的设置或文件；二是直接启动模式也安排了WorkManager后台同步。不能仅凭缺失堆栈的日志认定已经穷尽那次退出的全部原因。

## 修复

- 初始化字体、键盘配置、统计、语音/模型和剪贴板同步时保留设备保护上下文；全局数据上下文也使用当前启动模式对应的上下文。
- 解锁前的Rime数据使用应用自己的设备保护目录，暂不使用共享rime目录或SAF同步；用户的目录设置保持不变。
- 基础资源校验记录按实际资源目录保存，避免普通模式已经复制过资源而跳过解锁前目录的首次准备。
- WorkManager在用户解锁、凭据存储可用后启动，应用入口及手动重排入口都检查；重复启动不会再次initialize。调度失败会记录原因，不把键盘进程一起终止。
- 解锁仍沿用原有的独立进程重启切换方式，停止引擎失败不再阻止正常退出；锁定启动阶段不尝试打开设置中的崩溃窗口。

## 日志

Java未捕获异常和应用初始化异常同步保存到设备保护目录，保留最近两次，每次最多64Ki字符，包括版本、线程、锁定状态、堆栈及cause。普通日志导出也能附带历史崩溃，不再只能从崩溃弹窗中取得。锁定阶段的生命周期日志可在解锁后一起导出；旧崩溃明确标注为历史记录。

原日志中另有用户主题YAML第42行语法错误、旧液态键盘类型不兼容及旧动作名警告。它们不是本次已证实的崩溃堆栈；本轮未修改用户主题文件。

依据：[WorkManager官方API](https://developer.android.com/reference/androidx/work/WorkManager)、[Direct Boot官方说明](https://developer.android.com/privacy-and-security/direct-boot)。本项目使用WorkManager2.9.1，本轮未升级依赖或更改JNI。

## 验证边界

咩2使用隔离设备保护上下文验证，不重启手机、不切换默认输入法、不替换正式应用。整机实际关机、首次解锁到正常模式的过程仍需装入修复版后确认；不能用隔离检查声称已完成真实重启复现。

本轮不上传GitHub，交付正式APK、咩2、完整源码、补丁与说明。
