# V3.7.7 主题工具栏串用修复

2026-11-15 完成的本地修复，未单独打标签，已随 V3.7.8 正式发布。基于已发布 V3.7.5 的提交 `f2fd3039e51226329c1af5b29d1c579b65b6cf5f`，包含 V3.7.6 季灾兑换码 `qxm222`。

## 根因与证据

旧主题工具栏编辑只保存一份全局 `configured/buttons`，切换主题时会继续读取同一份 `toolbar_overrides.json` 覆盖当前主题。保存的记录主要引用动作名，未按主题隔离。

当旧动作在当前主题工具栏中不存在时，`ToolbarOverrides.applyEntries` 的 `allowCustomActions` 分支会创建一个只有动作名、前景为空的按钮。若当前主题预设也没有该动作，`KeyAction` 将未识别动作作为文本和标签，`ToolButton` 最终显示这个标签，因此出现 `keyboard_clipboard`、`jiantai`、`ziji`、`fanyi` 等英文。

用户确认简纯和Q之间切换后，按钮和顺序完全一致。之前保留的Q主题源文件使用 `Clipboard_window` / `ic@clipboard` 等定义，没有这些截图动作；据此结合共享覆盖路径定位。V3.7.6 的兑换码修改没有改动主题、字体和工具栏代码；旧全局配置在启动时重新读取。未取得该机当前配置文件，旧按钮最初来自哪个主题/哪次编辑无法从现有材料进一步确定。

## 修复行为

- 工具栏按钮、排序、停用、主按钮和恢复默认按主题源配置ID保存；相同显示名称但不同来源的主题仍相互独立。
- 旧全局记录完整保留。仅当每一个动作都能在当前主题或独立内置功能/快捷键中解析时，才迁移到一个兼容主题；不兼容的主题立即使用自己的原工具栏。
- 迁移只认领一次，不再把旧列表复制到其它主题。明确空工具栏仍保留为空。
- 恢复默认只作用于当前主题，并记录重置状态，避免重新读出旧全局覆盖；其它主题编辑和菜单隐藏记录保留。
- 主题导入/解析也只读取对应主题的覆盖。自定义布局继续使用各自独立工具栏。
- 本轮不改主题文件、字体文件、字体设置、输入方案或用户词库。

## 验证范围

- 390项主题、键盘配置和宠物单元测试全部通过。新增9项存储/迁移测试及1项应用集成回归：截图动作的旧JSON不覆盖Q、延后认领到兼容主题、只迁移一次、同名主题隔离、空列表语义、单主题恢复、快捷键、部分不兼容时整体回退、JSON保存恢复与编辑列表快照、切换后恢复各自图标。
- 初次扩大回归时两个已有模式筛选测试因未初始化 Android 偏好环境失败。为工具栏构建入口增加可选的已解析图标尺寸输入，测试显式传0；生产调用仍默认读取原有尺寸配置。之后同样390项全部通过，初次记录保留。
