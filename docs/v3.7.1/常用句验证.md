# 常用句发送识别修复验证

用户反馈：另一台设备的 QQ 中开启学习后，三次输入“好了好了这下好了”并直接发送，无句号，未学习成功。

自动上屏的文本原本已进入缓冲。修复完成边界与生命周期：光标归零时核对编辑框前后均为空，不再要求旧光标非零或旧 composing 标记已清除；同一编辑器 restartInput 先处理清空或保留草稿，去除 onStartInputView 的重复重置。纳入实际写入编辑器的候选预览，编码浮层里的未上屏候选不计入。读取失败不判定发送，删除清空不学习。

62项相关本地回归通过（句子19、统计22、输入核心21）。PKX110 Android16/API36 自有 EditText 中，通过 IME 引擎提交入口分片输入用户原句：普通清空、清空并 restartInput、中途 restartInput 后继续输入三组，每组三次，均只学习完整原句、频次3。原有三种行内模式触屏补全、浮窗尺寸/避让、学习开关、删除、隐私元数据和容量检查通过。正常/左右单手模式编码变化时，应用预留区域保持不变。

另以独立 Lua 测试翻译器生成真实“好了”候选，先提交“好了好了这下”，最后两字以行内预览写入编辑器后由应用直接清空，三次后完整原句频次3，逐步前后状态均有记录；清空后同步清除旧引擎组合，避免候选残留。

这是真机自有编辑器模拟，未在反馈设备的 QQ 真实发送；巧码本轮覆盖为引擎提交片段接入，未重跑反馈设备的实际方案。最终设备补测已包含过时归零保护和真实行内候选清理。原 V3.7.0 测试使用句号完成，未覆盖直接发送，本轮补测此路径。
