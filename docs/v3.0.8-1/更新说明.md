# V3.0.8-1 开发记录

本版是 V3.0.8 之后的功能累积测试分支，**不升级正式版本号、不发布正式包**。正式渠道继续保持 V3.0.8；
本分支测试包使用独立包名 `com.osfans.trime.debug.v2`，可与正式版同时安装。

## 六项改动

1. **长时间切走再切回后键盘/主题失效**
   - 定位：librime 的 `detect_modifications` 会把数据目录本身的 mtime 当成修改。Android 共享存储上目录 mtime
     会被媒体库扫描、userdb/log 改名等刷新；实测 `/storage/emulated/0/rime` 目录 mtime 为 13:38，
     而顶层 YAML 最大 mtime 为 09:56:45、`last_build_time` 为 09:56:54，源文件并没有变。
   - 方案：不再让 librime 自己按目录 mtime 判断；新增 `RimeStartupMaintenance` 只比较共享目录/用户目录
     顶层源 YAML（排除 `user.yaml`、`installation.yaml`）的最大时间戳与 `user.yaml` 的 `var/last_build_time`。
     只有新建/编辑过源文件才在启动后调用启动桥新增的 `startRimeMaintenance(true)`，部署在 librime 工作线程
     后台执行，不阻塞键盘；重命名/删除不会改变最大时间戳，因此不触发。
   - 不替换/不重编 `librime_jni.so`：图一的 librime 补丁思路可行，但同样的语义可以在现有启动桥和前端完成，
     不必改动 V3.0.7 保持字节一致的原生引擎。构建缺失时仅在存在 `*.schema.yaml` 时自动补建，空数据的
     新安装仍沿用 V3.0.7 的手动首次部署流程。
   - 同时把 `ThemeManager.init` 从“等 Rime 就绪”解耦：主题只读文件，先初始化；Rime 慢或启动失败时
     输入法仍能显示键盘和主题，不再因为 `themeScope == null` 让 `onCreateInputView` 返回 null。
2. **悬浮球并入悬浮候选窗**：候选窗被关闭（`show_candidates_window=禁用`）时不再单独显示悬浮球，
   避免挡住工具栏的候选栏开关；开关仍然随时可改，只在候选窗存在时生效。球状态整体上移 12dp，
   减少与悬浮键盘工具栏/手势区按钮重叠。
3. **悬浮球手势**：单击展开工具栏（原行为）；双击打开键盘功能菜单（原长按行为）；
   长按打开扇形菜单。扇形菜单沿用工具栏按钮编辑器，可新增、修改、删除，最多 6 项，标签最多 4 字，
   动作通过 `performFloatingToolbarAction` 执行。默认四项：候选/悬浮/单手/剪贴。
   修复扇形布局：原角度落在下半圆并把按钮全部顶到弹窗底部，现改为上半圆，按钮完整显示在球上方。
4. **未开夜间跟随时无法切换配色**：`ColorManager.setColorScheme` 只在“跟随系统夜间模式”已开启且当前为夜间时
   写夜间槽位，否则写日间槽位，避免系统深色但未跟随时选择被解析器忽略。
5. **主题文件改动免完整部署**：主设置右上角菜单新增“刷新当前主题”，只对当前主题执行
   `deploy_config_file(themeId, "config_version")` 后重新加载，不运行方案维护。单测和实机均验证改动立即生效。
6. **自定义键盘素材目录屏蔽相册**：`DirectExternalStorage.resources()` 在
   `mie_resources/<包名>/` 根目录创建 `.nomedia`，覆盖 `custom_kb_bg`、`custom_fonts` 等全部子目录。
   实机对照：同一张 JPEG 放在该目录外会被 `content://media/external/images/media` 收录，放入该目录内
   即使主动发扫描广播也查询不到。
