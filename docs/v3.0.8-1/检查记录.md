## 已知边界

- 自动维护只在源 YAML 最大时间戳晚于 `last_build_time` 时触发；沿用 librime 的规则，部署失败时
  `last_build_time` 仍会更新，下一次不会自动重试，需要再次改文件或手动“部署”。
- 首次安装且没有任何 `*.schema.yaml` 时不自动部署，保持 V3.0.7 手动首次部署流程。
- `RimeFinalize` 会 join 维护线程；如果正在编译大型词典时切走输入法，退出可能等待编译完成（改动前
  自动部署也有同样行为）。只在文件确实变化时出现。
- 扇形菜单最多显示 6 项、标签最多 4 字；动作沿用工具栏按钮动作，参数化命令的参数需在编辑器中填写。
- 主题刷新只编译当前主题；使用前端不支持 DSL 的主题仍依赖完整部署，失败时会提示。

## 第四轮（2026-10-31）：切输入法疑云、功能代码查询、版本信息修正

1. **"杀后台自动切到 fcitx5 是不是同文崩了"** — 查证结论：不是崩溃。证据：
   - `dumpsys activity exit-info com.osfans.trime.debug.v2`：32 条历史退出全部是
     USER REQUESTED(10)/FORCE STOP(21)/PACKAGE UPDATED(16)/REMOVE TASK(22)，没有一条 reason=1 (CRASH)；
     正式包 com.osfans.trime.mie 的退出记录同样无 CRASH。
   - logcat 崩溃缓冲与应用内 mie-last-crash.txt 均为空。
   - 现场复现：把测试包设为默认输入法并唤起键盘 → `am force-stop`（无任何异常日志）→
     系统立即把默认输入法自动切到另一个输入法（本次切到 asrkb，之前那次切到 fcitx5）。
   结论：这是 ColorOS 在默认输入法进程被杀（清后台/force-stop）时的自动兜底切换，不是同文崩溃。
   用户反馈的"清后台后崩溃+无限闪退"属另一问题（其设备上的统计页崩溃），防御见第三轮。
