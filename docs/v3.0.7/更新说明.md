# V3.0.7 手动部署

## 行为

普通启动只加载已有部署文件。切换其它输入法后切回、进程被系统回收后重建、更新配置、选择主题和恢复整包备份，都不再自动部署。首次安装、修改方案和词典、恢复数据或删除build后，需在设置页右上角菜单手动选择“部署”；工具栏部署动作和部署广播入口保留。

主题源码中前端支持的配置仍可直接读取；需要librime完整DSL的主题使用已有build文件，手动部署时统一编译主题。未部署的新主题可能暂时回退到默认主题。

用户词典同步属于独立的数据同步操作，原有手动/定时同步设置保留；同步回调与部署回调已区分，不再冒充“正在部署”通知，不清空日志或重编OpenCC；同步不运行方案workspace_update部署。

## 实现

旧JNI的startupRime无论fullCheck为true还是false都会调用start_maintenance；false只表示先检测修改，不能禁止部署。本版普通启动使用独立的libtrime_startup.so，通过原引擎公开的版本化RimeApi执行setup、initialize、部署任务注册和消息回调注册，不调用start_maintenance。手动部署继续使用原JNI完整部署路径。

原librime_jni.so保持原字节和签名边界；新增桥从随包C++源码构建，支持16KiB页面。正常预编译构建只需NDK与CMake3.22.1，不需要重新获取librime子模块。完整源码构建入口也加入该桥。

移除ThemeLoader读取主题时的deploy_config_file调用；显式部署完成后依次编译主题，再请求刷新当前主题。备份恢复消息改为提示手动部署；旧deploy偏好不会在启动时执行。

方案列表保存和选择外部同步目录也不再自动部署；保存/导入完成后提示用户到设置菜单手动部署。
