# 自定义键盘制作规范（V3.1.16）

## 需求与结构

本目录维护六风格与清新四色两套可导入的自定义键盘。保持原有配色、布局和按键绑定，修复辅助页返回与中英返回丢失主布局的问题；九键最右列统一 15% 宽度。

每个风格使用一个稳定主 ID，例如 `custom_neon`；9/14/18 等中文主布局使用自己的 ID 并开启 `lock: true`。它们和数字、英文、符号、布局选择页都通过 `mie.secondaryOf: custom_neon` 归于同一主键盘。文件 ID 与名称分开：名称可中文，ID 不随改名变化。没有数据库/API服务；数据契约为 `mie.format: trime-custom-keyboards-yaml`、`preset_keyboards` 和每页 `mie` 元数据。

## 必须遵守的导航契约

1. **返回最近中文主布局**：数字、主题、布局等页面的“返回”用 `click: Keyboard_default`。禁止写死 `Keyboard_custom_neon`，否则 9/14/18 返回会丢失。符号子页回到符号分类页可保留显式页 ID。
2. **明确选择布局**：布局列表中的“26键”必须显式绑定 `Keyboard_custom_neon`；9/14/18 绑定对应 ID。不要把所有主 ID 跳转替换成 `.default`。
3. **中英切换**：工具栏使用 `Mode_switch`；中文页配置对应 `ascii_keyboard`，英文页不要将中文返回写死为 26 键。这样应用可以恢复进入英文前的中文布局。
4. **键盘样式入口**：工具栏皮肤按钮使用下面的通用动作，由应用动态列出当前类别；不要固定跳到某个颜色的 `_themes` 页面。

```yaml
action: '__mie_action:{"send":"FUNCTION","command":"theme","label":"键盘样式"}'
```

V3.1.16 提供主题布局、自定义布局、内置布局三类入口；这里制作/导入的皮肤属于自定义布局。旧 `_themes` 页可保留作旧文件的显式导航目标，新增皮肤无需手工加入应用的主题列表。

## 几何与图标

- 每行键宽合计为 100；九键最后一行依次 16/12/45/12/15，最右列四行均为 15。
- 每行显式标明 `mie.row`；占位键无绑定，不用绑定覆盖其它键来对齐。
- 图标用相对路径 `icons/<风格>_<语义>.png`，独立命名，不冒用应用内置图标文件名。统一笔画、视觉大小和留白，透明底，设置明确 `iconSize`。
- 字体、字号、阴影与背景保持每套键盘独立；导出主键盘时包含所有 `secondaryOf` 指向它的子页。

## 制作流程与本次变更

需求 → 本规范的结构/存储/动作契约 → 修改生成器 → 生成 YAML → 查看差异与构建/设备检查结果。以生成器为源，禁止只改产出的 YAML。

本次修改 `gen_styles.py`、`gen_fresh.py`，重新生成两份 YAML；没有更改图标文件和符号数据。生成过程完成，未运行自动测试或设备测试。

后续验收时逐一检查：26/9/14/18 → 数字/符号/布局页 → 返回；中文 → 英文 → 中文；显式选 26；切换颜色后的返回；两种外部皮肤包合并导入时 ID 与图标不冲突。保留原用户数据，不覆盖正式版作测试。

## 重新生成

```sh
python3 gen_styles.py
python3 gen_fresh.py
```

应用会记忆当前布局。导入修复文件时选择合并，并确认覆盖本目录原同 ID 页面；只重新安装应用不会自动替换已导入的旧皮肤。
