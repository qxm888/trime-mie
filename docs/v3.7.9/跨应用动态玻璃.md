# 跨应用动态玻璃

V3.7.9 新增独立内置整套“液态玻璃·动态”（`custom_liquid_glass_live`）。原“液态玻璃”（`custom_liquid_glass`）及之前签名 APK 均保留，两个主题各有完整十五页。2026-11-15 经用户授权随 `v3.7.9` 正式发布。

## 使用

键盘工具栏样式按钮 → 布局 → 内置布局 → 液态玻璃·动态。键盘和悬浮候选窗统一玻璃风格；选回“液态玻璃”可恢复自带背景的版本。

动态版需要 Android 12+ 且系统允许窗口模糊。系统关闭模糊或拒绝子窗口时，自动使用可读的自带背景；关闭键盘、换主题或销毁输入视图时移除模糊窗口。

## 实现与根因

之前的局部背景模糊通过反射调用隐藏的 `ViewRootImpl.createBackgroundBlurDrawable`，调试手机返回 `unsupported`。这不能推导为手机不支持公开窗口模糊：本轮 `WindowManager.isCrossWindowBlurEnabled` 实际为 true，公开接口实测成功。

动态版在输入法窗口下方创建不接收触摸、不获取焦点的 `TYPE_APPLICATION_MEDIA` 子窗口，使用公开的 `Window.setBackgroundBlurRadius(80)`。子窗口只覆盖键盘或悬浮候选区域；实际内容由系统合成器实时处理，按键与候选文字仍在输入法层清晰绘制。使用父输入法自身的窗口令牌，不申请悬浮窗或屏幕录制权限，也不自行抓取其他应用画面。

窗口布局只在显示状态、尺寸、位置或配置改变时更新。静态显示不另开逐帧抓屏或 CPU 滤波循环。模糊半径最多 150px；本主题默认 80px。没有新增运行时依赖。

`getGlobalVisibleRect` 返回根视图坐标，必须加上根视图在屏幕上的位置，才能处理状态栏及横屏导航栏偏移。视图缩放时同步模糊区域与圆角；候选隐藏、切换主题及输入法隐藏时清理窗口，系统模糊开关重新开启后恢复。

参考 [Android 官方窗口模糊](https://source.android.com/docs/core/display/window-blurs)、[公开窗口类型](https://developer.android.com/reference/android/view/WindowManager.LayoutParams#TYPE_APPLICATION_MEDIA)、[View 坐标说明](https://developer.android.com/reference/android/view/View#getGlobalVisibleRect(android.graphics.Rect))。运行时效果仍取决于设备支持和背后应用实际绘制的窗口内容。

## 验证

147 项布局、主题及外观单元测试通过。完整 Lint 仍有 90 项既有错误，本轮新增错误为 0；版本兼容检查和签名结果随本地包交付。

在 Android 16 / ColorOS 调试机上，以单独包名 `dev.codex.glassfixture` 的合成应用为输入目标，输入法仍为独立测试包；没有读取真实聊天内容。蓝色/橙色格纹背景改变后，键盘底色实时跟随，细格纹被平滑而按键文字保持清晰：同一区域亮度标准差由约 35.91 降到 1.04；蓝色均值 RGB 约 (119,176,200)，橙色约 (214,165,123)。这些数值验证画面模糊与颜色跟随，不作为整机帧率或耗电测量。

已通过触屏按键输入至另一应用、悬浮候选双窗口、单手、悬浮键盘、横竖屏切换、目标应用使用 adjustResize 调整窗口大小、系统关闭模糊后回退与重开恢复、切回保留主题、隐藏/重开键盘及窗口数量清理。窗口边界用独立的屏幕坐标核对，已查看原生截图。

测试后已核对恢复原默认输入法、启用列表及系统模糊设置，卸载两个专用测试应用，确认没有残留的动态玻璃窗口。
