# Trime Mie V2.1.0 界面重构方案与 Sol 执行任务

## 目标与范围

在 V2.0.20 稳定源码（7f20536）上重构应用设置与编辑界面，使日常设置容易找到、复杂设置按需展开。保留现有输入、语音、主题、皮肤、数据和部署能力。正式版本目标为 V2.1.0，文件名 trime-mie-v2.1.0.apk。用户明确要求由 Sol 执行；不上传 GitHub，完成后整理源码和交接说明。

## 现状审计

- MainFragment 首页有 13 个左右的平级入口，输入数据与通用、候选、键盘、字体、语音、主题混排，任务层级不清晰。
- KeyboardSettingsFragment 直接生成整个 keyboard provider：悬浮尺寸、单手、候选行布局、背景、状态栏、声音、触感、手势与实体键盘快捷键混在长列表。
- 候选窗口设置在 CandidatesSettingsFragment，横向候选布局却在 keyboard provider；界面必须归并，但存储键不迁移。
- 全局按键与状态栏外观在键盘设置和两个编辑器的菜单中重复出现；主题视频在键盘设置和 KeyEditActivity 各有一套入口/弹窗。
- 整体背景开关在设置页及 SkinPicker 多种背景弹窗重复提供，容易误认为是当前布局选项。
- 字体在首页，主题另起页面；应用明暗模式在高级设置，用户难以区分应用外观与输入法皮肤。
- 数据导入导出隐藏在剪贴板设置，实际应归数据与备份。
- 基础设置已有 Material 3 和浅色/深色资源，PaddingPreferenceFragment 已绘制分组圆角；应完善此系统，不引入 Compose 或其他 UI 库。
- PersonalizationActivity 等页面使用满屏描边按钮，和偏好设置页风格不统一。

## 导航与唯一设置归属

首页只保留以下六项主入口，具有图标、标题、简短摘要。顶部提供搜索设置与试打入口；部署放入输入方案页或顶部更多菜单，避免和日常导航争夺注意力。关于包含版本号。首页标题使用 Trime Mie，删除占空间的标语。

| 首页入口 | 二级入口/设置 | 唯一归属说明 |
|---|---|---|
| 输入与候选 | 输入方案、用户词典、输入行为、候选栏、悬浮候选窗 | general 输入设置；keyboard 的横向候选布局/行数迁到此 UI；候选窗布局/位置/行数/悬浮球同组。系统语音服务选择归语音页 |
| 键盘 | 布局管理与按键编辑、工具栏编辑、单手与悬浮键盘、横屏布局、按键反馈、手势与长按、实体键盘 | 单手/悬浮键盘和悬浮候选窗分开命名；隐藏状态栏在工具栏设置归属；符号/提示显示在键盘显示组 |
| 外观 | 主题与配色、背景、按键与状态栏样式、字体、应用外观 | 全局主题视频、整体背景开关、边框/圆角/模糊只在此处编辑。应用深浅模式与键盘主题跟随昼夜明确区分 |
| 便捷功能 | 语音输入、剪贴板、输入统计 | 语音模型/下载状态保留，系统语音服务选择归此；剪贴板只保留监听/建议/清理规则等 |
| 数据与备份 | 数据位置与同步、导入导出、配置维护 | 接入原 ProfileSettingsFragment 和 DataTransferActivity，不改变目录或部署规则 |
| 高级与关于 | 系统兼容、诊断与日志、开发者、关于与开源许可 | 应用图标/系统手势兼容保留；主题诊断可作为此处的同一页面快捷入口 |

每个持久化设置只有一个设置页面归属。快捷操作（输入法菜单中的开关、试打、部署）允许保留，必须读写同一原始键。编辑器中的全局外观改成“全局外观设置”跳转，不再原地打开另一个全局编辑器。主题视频入口同样改为同一背景页跳转。背景弹窗删除重复的整体背景开关，在外观背景页保留唯一开关。

搜索覆盖实际二级页面和关键设置（如语音、视频、模糊、悬浮球、单手、候选、剪贴板、同步），结果显示路径并跳到对应页面/分组。不能只有静态无效结果；索引应与导航定义共用来源，避免新增设置继续散落。

## 设置分组与状态

- 单手与悬浮：单手宽度/左右手；悬浮开关/横屏自动悬浮；尺寸/保持比例/偏移/圆角为可折叠高级项。
- 按键反馈：声音、振动、播报、按下气泡，子参数按依赖启用，不丢失原有依赖逻辑。
- 手势：滑动距离、速度、长按、重复、双击、滑动步长；实体快捷键单独折叠组。
- 候选：横向候选与悬浮候选分组；悬浮球默认关闭且仅隐藏状态栏时生效，保留透明度和说明。设置页可显示状态依赖摘要，不重置用户开关。
- 外观的三层作用域始终明确：全局样式 / 当前布局默认外观 / 单键覆盖。编辑器显示当前对象，并保留“跟随默认/清除覆盖”语义。避免重写已有渲染优先级。
- 保存型编辑器继续使用草稿和保存/应用，取消不落盘；即时开关不伪造“应用”步骤。返回和旋转需保留当前页面或已有草稿机制。

## 视觉规范

沿用原生 Material 3。使用已有主色、浅色淡暖底、深色中性底，不把粉色硬编码进组件。页面边距 16dp、组间距 20–24dp、组卡片圆角约 20dp；普通设置行最小 56dp，带摘要约 72dp，随大字体扩展。标题 20–22sp、正文 16sp、摘要 13–14sp。图标统一 24dp，交互目标至少 48dp。

将同一任务的行合为一张分组卡片，用细分隔或留白分层；避免每行一个巨型胶囊。折叠项使用箭头、摘要和清楚的展开状态，不能只靠颜色。编辑器保留实时预览，结构/按键内容/外观参数组织清楚。字体与语音页用设置行和分组替代大量描边按钮；导入/下载/取消等真正动作保留按钮。使用轻量展开/页面转场，遵守系统动画设置，不添加输入路径动画开销。

## 实现边界

1. 复用 PreferenceDelegateUi 和现有 SharedPreferences 键、默认值、依赖关系；不要复制一套设置存储。可增加按 key 选择/分组的 UI provider，统一监听与 direct-boot 同步。
2. 保留旧 NavigationRoute 可调用，旧入口映射到新归属页，不使 IME 菜单或 Intent 失效。ActivityResult 图片/视频选择生命周期保持正确。
3. 不改变 Rime 加载、配置目录、语音引擎、动态模糊实现和正式包名；不启用 rime-mie 嵌套或 Wanxiang 开发渠道。
4. 改动集中 app 设置/编辑 UI、资源和必要导航基础设施，不大范围重写 IME。
5. 仅使用稳定 checkout；不得批量提交原始开发目录或包含签名文件。

## 交付顺序

A. 建立导航/功能索引和六类首页；重组设置并消除重复编辑入口。
B. 统一设置分组、字体/语音及编辑器入口风格，保留各业务能力。
C. 检查资源和编译；整理每个原设置到新路径的映射，确保没有遗漏。
D. 若设备可用，检查咩2的首页、外观、键盘、候选和搜索实际界面，不能用万象版；若未做设备检查，明确记录。未经用户追加要求不新增或运行自动化测试。
E. 版本 V2.1.0、本地正式 APK、源码与变更/交接说明；不上传 GitHub。签名秘密不进入源码、日志或交接包。

## 验收要点

- 六类首页清楚，无重复平级设置；搜索结果可到达。
- 原有设置全部可达，旧值不丢失，跨页修改后的依赖/摘要及时更新。
- 全局背景/样式集中；当前布局和单键外观不被混成全局设置。
- 窄屏、大字体、深色下不裁切；返回路径合理，试打入口可用。
- 当前版本显示 V2.1.0；正式文件命名正确。
- 如有未完成项，明确列出；不能将仅方案或编译通过称为完成全部 UI 验证。
