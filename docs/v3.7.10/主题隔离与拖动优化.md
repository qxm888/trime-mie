# V3.7.10 主题隔离与拖动优化

2026-11-15 经用户授权正式发布，标签 `v3.7.10`，版本码 20271124，包名 `com.osfans.trime.mie`，沿用原签名。Release 提供 arm64-v8a APK、完整标签源码、V3.7.9 起增量补丁、验证记录与 SHA-256 校验值。

## 根因与修复

`SurfaceAppearance.keyboardScopedConfigs` 原来把指定页面的整套、当前活动键盘和 YAML 主题全局外观放进同一份候选配置；模糊与渐变再取其中第一个已启用值。因此查看另一套内置键盘时，若液态玻璃仍处于活动状态，已关闭模糊的主题也能读到玻璃效果。圆角读取同样可能跨整套。重建窗口期间还可能读取上一窗口保留的 `lastAttachedId`。

现在只从页面所属整套取配置，活动页须属于同一整套才可参与；有独立外观的内置布局不再继承 YAML 主题全局外观。新窗口未挂载键盘时使用它自己的初始活动页，避免沿用上一窗口的页面。原主题自己的阴影、亮边、渐变等设定保留，不做全局清空或重置用户布局。

## 拖动优化

- 浮动位置改变时，改为发起绘制遍历更新触摸区域，不强制整个输入法重新测量布局。窗口大小确实变化的路径继续正常布局。
- 候选窗仅在可用父区域尺寸变化时请求布局；障碍区域移动只重定位。
- 外观作用域按配置引用及版本比较，不在每次绘制时拼接大段 JSON 缓存标识；每轮配置计算只读取一次所属整套。
- 动态玻璃移动时仍保持系统实时模糊，半径暂时限制为 32px；停止移动 160ms 后恢复主题设定（内置主题默认80px）。不是关闭效果或改用屏幕截图。停止回调在隐藏、销毁和切换主题时清理。
- 窗口位置仍随移动更新，但不再为每个位置变化格式化边界字符串及记录状态日志。

参考 [Android ViewRootImpl](https://github.com/aosp-mirror/platform_frameworks_base/blob/master/core/java/android/view/ViewRootImpl.java)：绘制遍历也会分发内部触摸区域计算，无须为了位置平移请求完整测量。本轮已用移动后实际系统触屏输入验证触摸区域更新。

## 验证状态

149 项布局、外观与主题测试通过，包括所有当前内置页面在玻璃主题活动时的整套隔离；Debug Lint 90 项既有错误，新增0。

Android16 / ColorOS 真机使用独立合成编辑器，对比同一路径180次移动回调。旧版两种配置查询均使14套其他内置主题误读到动态玻璃，修复后均为0；切回云汐、薄荷、瓷白也没有原生模糊窗口残留。

| 悬浮键盘全局布局回调 | 179 | 0 |
| 候选窗全局布局回调（正确可用区域） | 0 | 0 |

帧回调间隔约16.58ms，未宣称刷新率由此提升。短时数据会随系统调度、设备状态波动；前面修复版轮次键盘 P95 也观察到约22.23–24.68ms，候选窗在正确可用区域下曾约21.03ms，不能把最终一轮当作固定收益或承诺所有机型零卡顿。原始 `over_refresh_budget` 字段按屏幕标称刷新率计算，本轮回调约60Hz，不将它解释为掉帧率。

检查还包括：将悬浮键盘向上移动到原可触摸区域之外，以系统真实触屏点击移动后的英文键，文字成功写入独立应用；候选浮窗风格截图已查看。最初诊断工具的候选高度与服务实际可用区域不一致，造成180次人工重布局；最终对比已统一为服务提供的实际尺寸，保留的对比记录使用修正后的条件。

测试后恢复原输入法、启用列表及系统模糊设置，卸载两个专用测试应用并确认无残留模糊窗口。原签名 Release、16KB ZIP 对齐及 APK 的 API34 专属监听引用检查通过。经用户授权发布 GitHub，其他设备的实际使用效果仍需后续反馈。
