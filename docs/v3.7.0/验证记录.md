# V3.7.0 发布与实测报告

测试时间：2026-11-13 20:21 CST。设备：PKX110，Android 16 / API 36。

最终结果：常用句功能与容量性能测试 PASS；普通/左手/右手编码区域检查 PASS；本地 58 项回归测试全部通过。正式 release 构建和 Lint 通过，原签名及16KB对齐验证通过。

真机功能/性能数据采自同一功能源码的独立Debug测试包。V3.7.0仅调整发布版本标识，正式Release包另行构建、签名并核验；未为版本号变化重复安装正式包。

## 紧凑浮窗

已移除标题和大块留白，只显示最匹配的一句；单行省略显示、点击仍补全全文。示例“感谢gpt帮我做项目”实测宽 169.14dp、高 40dp。宽度随文字变化，上限220dp且不超过屏宽55%。现有候选悬浮窗开启、位于右下时，三种预编辑模式都验证了实际屏幕坐标不相交。窗口或候选几何改变时重新避让；无可用空间时隐藏联想提示。

## 功能覆盖

- 合成句子由中文分段提交和g/p/t软键事件组成：前两次不录入，第三次录入，频次为3。
- 禁用行内预编辑、显示编码、显示候选预览三种模式：通过真实触屏事件点击提示，最终编辑器恰好一份完整句子；点击补全不增加学习次数。
- 相同编码/编辑状态下，显示和隐藏联想窗的应用 contentTopInsets 相同。补全后原候选栏本身可能变化，测试不把这一变化归因于联想窗。
- 长按删除和关闭学习开关通过。
- 密码框、IME_FLAG_NO_PERSONALIZED_LEARNING：向真实控制器传入合成EditorInfo并验证记录数不变。此项验证控制器的隐私规则，未关闭手机安全键盘，也不声称由本输入法接管了系统密码框。
- 普通、左手、右手模式：空编码、短编码、54字符长编码及清空时，应用 contentTopInsets 不变；单手编码浮层保留触摸区域。

## 性能数据

预置5000条待学习、2000条常用句，含约200字符长的合成句子。前缀“性能”匹配大量常用句；先预热20次，再查询300次。查询在后台执行；下表包括协程调度和查询返回的总耗时。

| 项目 | 实测值 |
| --- | ---: |
| 查询 P50 | 0.926 ms |
| 查询 P95 | 1.698 ms |
| 查询最大值 | 5.027 ms |
| 关闭学习：按键处理 P50 / P95 | 18.655 / 49.709 ms |
| 开启学习：按键处理 P50 / P95 | 18.510 / 49.779 ms |
| 开启前后按键 P95 差值 | 0.071 ms |
| 关闭 / 开启学习：帧间隔 P95 | 16.580 / 16.580 ms |
| 句子收集器追加操作 P95 | 13.646 µs |
| 测试期间丢弃的学习事件 | 0 |

按键使用“关、开、关、开”四阶段，每阶段144个真实Rime处理事件，剔除每阶段前12个预热事件；每种状态保留264个样本。计时包含Rime任务及等待主线程空闲，不能等同于单个函数耗时或物理按键到屏幕的延迟。帧间隔使用Choreographer采样。本轮未见明显性能回退；这是一台手机、独立测试编辑器、合成方案下的结果，聊天应用和低性能设备仍需实际使用验证。100ms联想防抖是产品设定，不包含在上述数据库查询耗时中。

手机上的实际查询计划：

```
SEARCH sentences USING INDEX sentence_prefix (learned=? AND lookup>? AND lookup<?); USE TEMP B-TREE FOR ORDER BY
```

使用规范化键的显式BINARY范围查询，验证命中前缀范围索引。单元测试覆盖滚动7天边界、时钟回退、分段上屏、删除、超长文本、混合文字，以及中文/SQL通配符/增补Unicode字符的查询范围。

## 交付与恢复

启用：设置 → 便捷功能 → 学习与联想常用句，默认关闭。管理常用句可删除单句或清空全部学习记录。

正式包包名com.osfans.trime.mie，V3.7.0，versionCode 20271114，arm64-v8a，使用原工程签名。源码已同步至原V3.6工程，并保留此前自动上屏码长及单手浮层修复。源码压缩包与编译副本的app/src逐文件核对。

实测只使用独立临时包和生成文字。原默认输入法、启用输入法列表已逐项比对恢复，临时测试包已卸载；系统安全设置未修改。合成输入日志、测量JSON、单元测试XML及构建记录随BuildChecks-v3.7.0.zip提供，测试源码随仓库公开。
