# 词库自学习（第 1 层：统计学习闭环）

日期：2026-11-20（P1）/ 2026-11-21（P2）　状态：开发完成，待真机验证

## 目标

输入法在本地学习输入习惯：常用词自动排前（调频）、高频组合自动组成新词写入
用户词典（自动组词）、积累分词语料为后续整句智能排序（octagram 搭配模型）储备
原料。全程不联网、不采集密码框，总开关默认关闭。

## 架构与数据流

```
引擎 commit（Rime.emitResponse）
  条件：2~4 字纯中文 + 本次 commit 消耗全部编码（afterInput 为空）
        + 编码全小写字母 + 每字 2~6 码 + 字段允许个性化学习
  → CommitLearningLog.record → filesDir/learning/learning_log.jsonl（2MB 滚动）
后台 LearningWorker（每 6 小时，电量/存储不低时）
  → LearningAggregator.runOnce：
      1. 词频表 learning_freq.json（词→累计观察数+编码众数，上限 1 万条）
      2. 阈值（默认 5 次）词按方案分组 → TSV「词条\t编码\t频次」
         → UserDictManager.importUserDict（levers JNI）
         合并语义为取 max（user_db.cc UserDbImporter::Put），重复导入幂等
      3. 分词语料 learning_corpus.txt：按会话切行（间隔 >5s 或换方案），
         词间空格连接，保留词边界，1.5MB 有界
      4. 用户近 1 分钟无输入 → RimeDaemon.deploy() 让 userdb 生效
      5. 消费完删除日志；下次部署自然重载
```

## 关键实现依据

- **导入格式**：`TableDb::format`（librime `table_db.cc`）为
  `词条\t编码\t频次`；频次走 `UserDbValue.commits`，导出/导入对称
- **合并语义**：`UserDbImporter::Put` 取 `max(旧, 新)`，故导入累计观察数，
  不会重复叠加，与引擎自身的选词计数同源
- **词典名匹配**：`getUserDictList()` 返回的 userdb 名与观察时的方案 id
  按 `等于 / 去掉 .userdb 后缀后等于` 匹配，匹配不到则跳过（保守不写入）
- **防污染**：粘贴、剪贴板确认、整句连打、"/" 引导符号天然不满足
  「编码全消耗 + 2~4 字 + 每字 2~6 码」约束，不进学习日志

## 已知限制

- 编码仅支持全拼类（a-z）；注音等其它编码形式后续版本再支持
- 部署节奏：userdb 导入需要 deploy 后对新会话生效，当前为批处理后或
  用户空闲时触发

## P2（2026-11-21）：智能整句 / 学习词管理 / 下词联想

### A. octagram 智能整句（实验性）

- **数据**：官方预构建简化字模型 `zh-hans-t-essay-bgc.gram`（9.9MB，
  lotem/rime-octagram-data hans 分支）已打包进 `assets/learning/`；
  完整版 `zh-hans-t-essay-bgw.gram`（39MB）支持设置页手动导入
  （文件选择器，`.gram` 文件，language id 取文件名）。
- **新文件 `data/learning/GrammarSetup.kt`**：
  - 开启：拷模型到 `UserDataManager.userDataDir/<id>.gram`（librime
    native 读取的 user_data），对每个启用方案（`runOnReady` 内
    `enabledSchemata()`）写 `<方案>.custom.yaml` patch——
    `translator/contextual_suggestions: true` + `grammar/language: <id>`，
    然后同块内 deploy。
  - 关闭：只移除这两个 patch 键，模型保留。
  - patch 用 kaml 解析重建（保留用户已有 patch 键；文件会被重排，
    手写注释丢失，设置页已注记）。
  - octagram 按 `grammar/language` id 查 `<id>.gram`（user_data 优先，
    octagram.cc:21-47）。
- **设置页**：智能整句 toggle（默认关）+ 导入模型按钮 + 当前模型状态行。

### B. 学习词管理

- **新文件 `ui/main/LearnedWordsActivity.kt`**：RecyclerView 列表
  （词 / 编码 / 累计次数，仿造词管理样板），点击删除。
- **`LearningAggregator` 扩展**：`learnedWords()`（freq 表达阈值词条，
  按次数降序）、`removeLearnedWord(word)`——移出词频表 + 向所属方案
  userdict 导入 TSV `词\t编码\t-1`（librime `UserDbImporter::Put` 对
  `commits < 0` 标记删除，user_db.cc:264-265），随后 deploy。
- **入口**：设置页「管理已学新词」。

### C. 下词联想（词级 bigram 预测）

- **`LearningAggregator` 扩展**：聚合轮次从会话（间隔 >5s / 换方案切分）
  内相邻上屏词对统计 `learning_bigram.json`（前词 → 后词 → 次数，
  5000 前词上限、每词保留 top20 后继），内存缓存 + `predictNext(word)`。
- **`SentenceSuggestionController` 扩展**：commit 记录「最近的纯中文词」
  （2~4 字，与学习日志词条约束一致）；查询路径统一为
  「句级联想（原逻辑，prefix≥2）优先 → 未命中且词级开关开启时用
  `predictNext` 弹下词」。弹窗复用抽取的 `buildPopup`（圆角单行 + "×"），
  点击直接 `ic.commitText`（绕过学习钩子防自我加权）后 reset。
- **开关**：`wordPredictionEnabled`（默认关）；句级开关关闭时词级仍可
  独立工作。
