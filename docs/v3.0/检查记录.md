# V3.0 检查范围

检查机为已配对手机上的咩2包 `com.osfans.trime.debug.v2`，没有切换系统默认输入法。正式包生成后单独检查签名、版本和图标资源。

## 已完成的隔离检查

- 本机HTTP模拟SyncClipboard兼容接口：短文本和大文本附件往返一致。
- 图片和单文件字节往返一致，支持中文文件名。
- 损坏附件哈希、越界附件文件名被拒绝。
- 独立目录/命名空间内：布尔、整数、集合、浮点字体字号、键盘JSON和字体资源备份恢复；路径重定位保持统计和词典中的字面内容不变。
- 模拟新设备私有目录与Rime目录变更：重定位字体与键盘文件路径，并保留当前设备的数据目录选择。
- 模拟在文件重命名中间进程中断：回退并完成恢复；提交成功但清理前中断时，仍恢复完整部署标记。
- 17MB有效字体连续解析2000次保持对象身份，最终检查7ms，验证缓存不会因旧16MB权重上限立即淘汰。

独立检查使用生成数据和本机模拟服务，不读取真实服务密钥、不上传系统剪贴板内容、不改动真实布局和候选记录。代码入口 `app/src/debug/java/com/osfans/trime/benchmark/Mie30Runner.kt`，仅包含在检查包中。

## 验证边界

- 协议检查使用本机模拟HTTP端点，尚未连接用户的真实SyncClipboard/WebDAV服务器，也未验证不同桌面剪贴板实现。
- 字体检查证明缓存保持，不代表所有大字集字体、手机GPU与复杂方案都达到相同延迟。
- 流式接收路径已接入；尚未使用用户麦克风和付费服务进行真实语音回归。不同聊天应用对临时组合文字支持不同，可关闭流式输出回到最终结果上屏。
- 原生Control+Delete遵循当前方案配置，尚未改动用户真实词典以逐方案验证忘词效果。
- 模型迁移校验和旧路径兼容已实现，尚未完成所有多GB模型在不同Android版本上的迁移回归。
- 整包恢复文件逻辑做了隔离检查；重启界面和不同厂商系统恢复行为还需实机覆盖。

最终构建、界面截图、签名和文件校验值以交付目录的检查记录及SHA256SUMS为准。
