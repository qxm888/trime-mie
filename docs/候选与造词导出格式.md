# 候选调整与造词的多格式导出

## 入口

- “输入与候选 → 造词管理 → 右上角更多 → 导出全部造词”：导出全部方案的造词，不受当前搜索、筛选条件影响。
- “统计与候选备份 → 候选调整 → 导出候选调整”：导出各方案、各编码的应用内排序、隐藏、造词和搜索范围。
- 两处都先选择 YAML、JSON 或 TXT，再通过系统文件选择器保存。
- “导入候选调整或造词”自动识别三种格式。完整候选备份替换当前规则；仅造词备份合并词条，不覆盖已有排序及其它方案的记录。导入前另存原记录备份。

三种格式均使用 UTF-8，保留词句、符号、emoji、制表符和换行。文件大小上限为 32MB。

## 文件结构

- YAML：`format: trime-mie-candidate-records`、`version: 1`、`scope` 和 `records`。每条记录独立保存 `schema`、`code`、`order`、`aliases`（造词）、`hidden` 和 `searchLimit`。
- JSON：完整候选备份沿用旧版 `version: 1`、`rules` 映射结构，增加可忽略的 `scope` 字段；映射键仍是紧凑 JSON 编码的 `[方案,编码]`。仅造词文件使用 JSON 版本 2，防止旧版应用把它误当完整备份而替换全部调整。
- TXT：首行标识格式、版本及范围；其后是 `type / schema / code / position / text / search_limit` 六列，以制表符分隔。`rule` 行保存编码设置，`order` 行按位置保存候选顺序，`created` 保存造词，`hidden` 保存隐藏。位置从 1 开始连续排列。反斜杠、制表符、回车、换行分别转义为 `\\`、`\t`、`\r`、`\n`，导入时还原。

仅造词文件的 `scope` 为 `createdWords`，完整候选文件为 `candidates`。数据先解析和校验，再一次性写入；格式错误不覆盖当前记录。

## 与 Rime 词典的区别

这些文件用于保存、迁移应用内造词与候选调整。生成 Rime 词典继续使用“生成词典草稿 → 导出各方案词典草稿 ZIP”，其中包含 `.dict.yaml` 和接入说明。

原生 Control+Delete 忘词及 Rime 学习到的词频属于用户词典，需通过用户词典或整体备份保留。
